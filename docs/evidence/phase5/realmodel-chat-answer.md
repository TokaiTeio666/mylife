结论：近期围绕向量检索学习了检索配置、缓存优化、性能排障和量化优化方法，并安排了模型召回对比任务。[1][2][3][4][5]

- **检索配置**：HNSW 语句超时固定为 250 毫秒；查询向量采用 256 条 LRU 缓存，避免重复调用 embedding 服务；自然语言问题使用 RRF 融合。[2]
- **性能排障案例**：曾出现“查询向量未缓存”的问题，根因是每次请求都重新调用 embedding，代价为 3 小时；正确做法是加入 256 条 LRU 缓存，高频重试是复发触发条件。[4]
- **优化方法论**：采用“先量化再优化”，步骤是测量基线、每次只改一处、重新测试；该方法适用于小数据量场景，验证指标是 P95 下降。[5]
- **待补内容**：需要补写 HNSW 压测，并对比 BGE-M3 与 nomic-embed-text 的召回效果。[1][3]
- **相关缓存知识**：缓存穿透可以先用布隆过滤器拦截；此前还梳理了缓存穿透与布隆过滤器的适用边界。[3][6]
